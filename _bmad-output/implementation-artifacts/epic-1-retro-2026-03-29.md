## What Went Well

- **Centralized cross-cutting concerns:** Request-id propagation and error handling registered once in `buildApp` (Story 1.4), inherited by every subsequent story. This pattern scales well and will carry into Epic 2 for free.
- **Schema-first contract design:** Route schemas as source of truth, OpenAPI regenerated from them, shared constants consumed by both API and web — zero drift across 7 stories.
- **Extend-don't-replace pattern:** Story 1.7 extended `useTodos` with `createTodo` rather than rewriting. Kept risk low and preserved existing test coverage. This pattern carries into Epic 2.
- **Vertical slice delivery:** From zero to a working app with real persistence, validation, and error handling in 7 stories. The incremental build-up was clean.
- **Deterministic test infrastructure:** `db:reset` for API tests and mocked `fetch` for web tests enabled confident, flake-free development.
- **Clean agent handoff:** Two different dev agents (GPT-5.2/5.3 for Stories 1.1–1.5, Claude Opus 4.6 for Stories 1.6–1.7) handed off cleanly thanks to strong contracts and patterns.

---

## Challenges

- **Focus management in React 18:** Required non-obvious workaround — state-based coordination via `useEffect` + `shouldFocus` flag because React 18 batches state updates (Story 1.7).
- **4 deferred tech debt items from Story 1.6:** AbortController, stale todos on retry, retry debounce, dark mode WCAG contrast. Three of these become actively relevant in Epic 2.
- **Biome auto-fix friction:** Both Stories 1.6 and 1.7 required manual `npm run biome:fix` runs for import formatting. Recurring friction that should be automated.
- **Missing `@testing-library/user-event`:** Web stories fell back to `fireEvent`, limiting keyboard interaction test fidelity.
- **Explicit `cleanup()` boilerplate:** Required in every web test file since vitest `globals: true` is not set. Team decided to keep this intentional.

---

## Key Insights

- Plain `fetch` + `useState` was sufficient for Epic 1's load-and-create, but will be tested harder in Epic 2 with concurrent mutations.
- Optimistic UI (Story 2.3) and server-confirms-first (Story 2.5) will coexist in `useTodos` — two different mutation patterns in the same hook.
- Per-item AbortController is the right concurrency solution but best built after mutation patterns are established (Story 2.6, optional).
- E2E tests should accompany feature development, not be bolted on at the end — Story 1.8 added to establish the safety net before Epic 2 mutations land.

## Decisions Made

1. **Per-item AbortController map (Option B)** selected as the concurrency solution — `Map<string, AbortController>` keyed by todo ID, separate controller for list fetch. Added as optional Story 2.6 at end of Epic 2.
2. **Retry debounce fix** folded into Story 2.1 — disable retry button while request is in-flight.
3. **Install `@testing-library/user-event`** in Story 2.2 — first web story with keyboard interactions (Enter/Escape).
4. **State-based focus coordination** pattern from Story 1.7 to be applied for inline editing focus transitions in Story 2.2.
5. **Pre-commit hook update** in Story 2.1 — run `source:fix` then `source:check` before `test:ci`.
6. **Keep vitest `globals: false`** — explicit `cleanup()` in tests is intentional.
7. **Extend `useTodos` incrementally** — one mutation per story, extract private internals into separate modules only if the hook grows too large.
8. **Click-outside-to-save** for inline editing (Story 2.2) — same as Enter, most forgiving UX.
9. **Story 1.8 added** — Set up Playwright E2E infrastructure and cover Epic 1 flows before starting Epic 2. E2E tests grow story-by-story alongside unit tests.
