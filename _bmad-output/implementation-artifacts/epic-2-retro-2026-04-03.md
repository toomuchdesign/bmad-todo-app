## What Went Well

- **Excellent Epic 1 retro follow-through:** 9/9 action items completed, 2/4 deferred debt items fully resolved. The team committed to improvements and delivered on all of them.
- **Review process caught real bugs in 5/6 stories:** Ref lifecycle issues (`cancelledRef` not reset, `savingRef` not reset on rejection), typing gaps (untyped error bodies, wrong response type keys), schema gaps (missing UUID format validation, missing 400 in DELETE schema). The review process proved load-bearing.
- **Incremental hook extension scaled cleanly:** Each story added one mutation to `useTodos` following the same pattern — clear error, fire request, update state, handle failure. Consistent patterns made the Story 2.6 unification straightforward.
- **Schema-first contract pipeline held:** PATCH and DELETE route schemas followed POST's template. OpenAPI regenerated cleanly each time. Zero contract drift across all stories.
- **Strong velocity:** 3 stories landed on day 1 (2.1–2.3), 2 on day 2 (2.4–2.5), final concurrency refactor on day 3 (2.6). Zero blockers throughout.
- **Testing grew incrementally:** Every story added tests at unit, integration, and E2E levels. The decision from Epic 1 retro to grow E2E story-by-story paid off — Epic 3's E2E story becomes gap-filling, not from-scratch.
- **Forward-looking design decisions:** The `pendingActions` map in Story 2.2 was designed upfront to support edit, toggle, and delete. Story 2.6's "abort + re-send with merged fields" solved cross-field data loss elegantly.

---

## Challenges

- **Growing `useTodos` complexity:** By Story 2.5, the hook had four mutation functions, a pending actions map, error state, and loading state. Story 2.6 (originally optional) became practically necessary to tame concurrency and unify the mutation patterns.
- **Deferred items accumulated:** 8 new `[Review][Defer]` items across Epic 2 stories, on top of Epic 1 carryovers. Most were pre-existing patterns or planned for later, but the debt surface grew.
- **Edge cases in concurrent/cross-tab behavior:** The 404-on-already-deleted-todo loop (Story 2.5) and stale mutation refs during retry (Story 2.6) are real UX gaps that affect test reliability.
- **Ref lifecycle bugs recurring:** Stories 2.2 and 2.6 both had ref management issues caught in review — `cancelledRef` not reset on re-entering edit mode, `savingRef` not reset on rejection, `clearController` not verifying controller identity. Refs require careful lifecycle thinking.

---

## Key Insights

- **Two mutation patterns coexist successfully:** Optimistic UI with rollback (toggle, Story 2.3) and server-confirms-first (delete, Story 2.5) both live in the same `useTodos` hook without conflict. The unified `updateTodo` in Story 2.6 handles both cleanly.
- **AbortController + field merging is the right concurrency model:** Abort + re-send with accumulated `pendingFields` prevents cross-field data loss. Server response replaces local state entirely — no partial reconciliation needed.
- **Reviews are worth the investment:** 5/6 stories had actionable findings. The bugs caught (ref lifecycle, schema gaps) would have been hard to reproduce in testing but could cause real user-facing issues.
- **Epic 3 story definitions need updating:** Story 3.2 title mentions "load/create" but now needs to cover edit, toggle, delete, and concurrency. Story 3.3 (E2E) is gap-filling, not from-scratch. Review before creating story files.

### Items to fix in Epic 3 prep story

- **A1:** Stale todos alongside error banner on retry failure — clear stale list or mark as outdated when re-fetch fails
- **A3:** 404 on already-deleted todo loops forever — treat 404 as success in `deleteTodo` and `updateTodo` (item already gone server-side, remove locally)
- **A4:** `fetchTodos` retry during in-flight updates leaves stale `pendingFields`/`snapshots`/`mutationControllers` refs — clear all mutation refs and abort in-flight mutations when `fetchTodos` succeeds
- **B4:** CSS hardcoded spacing/sizing values — abstract spacing, font-size, and border-radius into token files in `packages/web/src/tokens/`

### Items kept in deferred log

- **B2:** Pre-commit `source:fix` silently modifies staged files — ignore for now
- **B5:** Concurrent multi-item edit mode (blur-save on switch) — intentional architectural choice

### Items deferred to specific stories

## Decisions Made

1. **Add a prep story (3.0) at the start of Epic 3** to resolve A1, A3, A4, and B4 before quality/test stories begin.
2. **Treat 404 as success** in `deleteTodo` and `updateTodo` — the item is already gone server-side; remove it locally.
3. **Clear mutation refs on re-fetch success** — fresh server data is the new source of truth; abort in-flight mutations.
4. **Abstract CSS spacing into tokens** — create spacing, font-size, and border-radius token scales in `packages/web/src/tokens/`.
5. **Review Epic 3 story definitions** before creating story files — titles and scope assumptions predate Epic 2's test coverage.
6. **Keep A2 (error state collision) deferred** — acceptable for MVP.
