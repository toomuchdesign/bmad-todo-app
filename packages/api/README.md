# bmad-todo API (`packages/api`)

Fastify API workspace (TypeScript).

## Local prerequisites

- Node.js `>= 22.12` (see repo root `.nvmrc`)
- npm (npm workspaces)
- Docker runtime for local Postgres
  - macOS: we use Colima (Docker Desktop also works)
- `docker-compose` (or `docker compose`) to run local Postgres

macOS install hint (if you don't already have these):

```bash
brew install colima docker docker-compose
```

## Database

### Overview

The database schema is defined in `src/db/schema.ts` using Drizzle ORM. Structural changes are managed through SQL migration files in `drizzle/`, generated by `drizzle-kit`.

Migration files and their metadata (`drizzle/meta/`) are committed to the repo. Never hand-edit them — they are generated by `drizzle-kit generate`.

### Environment setup

API expects `DATABASE_URL`, `API_PORT`, and `API_HOST` (see root `.env.example` for the required keys).

- All env files live at the **project root** (`.env`, `.env.test`, `.env.example`).
- The API server and DB scripts auto-load the root `.env` via `env-schema`.

Start local Postgres from the repo root:

```bash
colima start # macOS only
docker-compose up -d
```

### Setting up a new database

Apply all migrations from scratch:

```bash
npm -w api run db:migrate:local   # dev DB (loads .env, starts Postgres)
npm -w api run db:migrate:test    # test DB (loads .env.test, starts Postgres)
```

### Making schema changes

1. Edit `src/db/schema.ts`
2. Generate a migration: `npm -w api run db:generate`
3. Apply it: `npm -w api run db:migrate:local` (and `db:migrate:test`)
4. Commit the generated files in `drizzle/`

### Production / CI

```bash
npm -w api run db:migrate         # expects DATABASE_URL set by the platform
```

Idempotent — skips already-applied migrations. Run on every deploy.

### Resetting data

```bash
npm -w api run db:reset           # truncates all tables (does not drop schema or migrations)
```

Used by E2E test setup and for local development when you want a clean slate without re-running migrations.

## Tests (env vars)

- Vitest auto-loads the root `.env.test` (see `vitest.config.ts`).
- Put test-only values there (for example, point `DATABASE_URL` at a dedicated test database).
- Reuse shared API test helpers from `packages/api/test/test-utils/index.ts` in all API tests.

## Timestamp contract

- DB columns use Postgres `timestamptz` (`created_at`, `updated_at`, `deleted_at`).
- API JSON always exposes these fields as ISO RFC 3339 date-time strings in UTC.
  - Example: `2026-03-28T15:42:11.123Z`
- OpenAPI schemas mark these fields with `format: date-time`.

## API entity definitions

- Canonical API building-block definitions live in `packages/api/src/definitions`.
- Each definition exports:
  - JSON Schema source of truth (runtime/OpenAPI contract)
  - TypeScript type inferred via `json-schema-to-ts` (`FromSchema`)
- Reuse these definitions in routes, DB mapping boundaries, and API integration test setup helpers.

## Scripts

Run these from the repo root:

```bash
npm -w api run dev
npm -w api run test
npm -w api run test:ci
npm -w api run type:check
```

Contract artifacts:

```bash
npm -w api run build:openapi
```

DB tasks:

```bash
npm -w api run db:generate        # generate migration from schema changes
npm -w api run db:migrate         # apply migrations (production/CI — needs DATABASE_URL)
npm -w api run db:migrate:local   # apply migrations to dev DB
npm -w api run db:migrate:test    # apply migrations to test DB
npm -w api run db:reset           # truncate all tables
npm -w api run db:studio:local    # open Drizzle Studio (dev DB)
npm -w api run db:studio:test     # open Drizzle Studio (test DB)
```
